# AgentGuard AI — ContextLock V3 Security Lab

**Status: Portfolio proof of concept, simulation only. Not a production security control.**

## What's new
- Case-wide refund budgets across **multiple mandates**, enforced under SQLite `BEGIN IMMEDIATE` transactions.
- Scope-bound infrastructure change mandates and human review for production actions.
- Idempotent request IDs and immutable final decision evidence (within demo constraints).
- Streamlit Attack Lab, approval review, decision evidence and optional **real LLM tool-call proposal**.
- FastAPI gateway and automated adversarial tests.

## Quick start (macOS / Linux)
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export AGENTGUARD_DB=agentguard_v3.db
python seed.py
python -m pytest -q
streamlit run app.py
```
Save the generated demo token locally. To start API in a second terminal:
```bash
export AGENTGUARD_DB=agentguard_v3.db
export AGENTGUARD_ADMIN_TOKEN="$(python -c 'import secrets;print(secrets.token_urlsafe(32))')"
uvicorn agentguard.api:app --host 127.0.0.1 --port 8000
```
Visit `http://127.0.0.1:8000/docs`. API gateway requests require `Authorization: Bearer <token>`. Admin endpoints require `X-Admin-Token: <value>`.

## Demo cases
1. Refund case `CASE-100`, budget ₹10,000 (`1000000` paise). Mandates `REF-A` and `REF-B` individually allow ₹10,000 but share the **case** budget. Run ₹6,000 + ₹3,000 + ₹4,000: third action blocked.
2. Change case `CHG-2041`. `CHG-STAGE` authorizes only staging; `CHG-PROD` authorizes production but requires human approval. After approving, resubmit **the exact same request ID and payload**.

**Important:** The seed script creates a new token every run and resets demo agent credentials; don't re-seed a running demo unless intended. Use a fresh database filename for repeatable attack runs.

## Optional actual LLM tool calling
Set `OPENAI_API_KEY` in your local environment and open the Agent Integration tab. The model can propose a `request_refund` tool call, but the ContextLock engine independently decides whether to simulate execution. This mode makes a network request and may incur API charges. The offline demonstration requires no API key. Do not send real customer data.

## Security boundaries and limitations
- The dashboard directly invokes the local service as a trusted demonstration harness; **it is not an authenticated public admin UI**. Run only on localhost, never expose it to the internet.
- The real LLM integration uses a single tool-call round trip; it is not a full multi-step autonomous agent orchestration framework.
- The gateway simulates downstream actions in SQLite. A real system must prevent agents from calling downstream APIs directly and must reconcile failed/uncertain downstream execution.
- SQLite is suitable for a local POC, not a distributed production authorization platform. No enterprise SSO, reviewer identity verification, tamper-evident external audit sink, rate limiting, or external policy engine.
- Human approvals are scoped to the exact request fingerprint and expire after 30 minutes. The dashboard's reviewer name is **not authenticated**.
- The demo token generated by seed.py is shared across two demo identities. Production systems require unique credentials per principal.
- Approval is stored before execution; retry the exact request to apply it. No background job executes approved changes automatically.
- Decision records are not tamper-proof against DB administrators.

## Next engineering steps
Authenticated reviewer roles, per-agent token separation, external policy evaluation, tamper-evident audit log, transaction outbox for downstream execution, proper SDK middleware, load/latency benchmarks, and browser-level UI testing.
